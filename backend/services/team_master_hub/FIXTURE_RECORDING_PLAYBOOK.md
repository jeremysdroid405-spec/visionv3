**Purpose:** define the exact lifecycle of recorded SGO event-odds

## 1. Directory layout

```
backend/tests/fixtures/team_odds/
├── README.md                    # auto-generated; lists every fixture
├── mlb/
│   ├── 2026-06-02_evt_001.json
│   ├── 2026-06-02_evt_001.meta.json
│   └── …
├── nba/
└── nfl/
```

- One `.json` payload per recorded event/snapshot.
- One sibling `.meta.json` per payload carrying provenance.
- `README.md` is regenerated by the CLI on every successful record.

## 2. File naming

```
<YYYY-MM-DD>_<event_id>[_<snapshot_idx>].json
```

- `YYYY-MM-DD`: the `commence_time` date in UTC.
- `event_id`: the SGO `event_id` field, sanitized to `[a-zA-Z0-9_-]+`.
- `snapshot_idx` (optional): zero-padded counter when recording
  multiple snapshots of the SAME event over time (e.g. opener vs
  closing line).

## 3. Required sanitization

EVERY fixture committed to the repo MUST pass `assert_sanitized()`
(see `services.team_master_hub.fixtures`). Rules:

1. **No API key anywhere.** The recorder strips the `api_key` query
   param from the recorded URL AND scans the payload string for the
   literal key value, replacing any match with `<REDACTED>`.
2. **No request headers.** We never persist Authorization,
   X-RapidAPI-Key, Cookie, or any header.
3. **No internal IPs / hostnames** beyond `api.sportsgameodds.com`.
4. **No PII fields.** SGO payloads don't carry PII, but a paranoia
   scan rejects any field name matching
   `(email|phone|ssn|address|password)` (case-insensitive).
5. **Sanitization version stamp** on every meta file
   (`sanitization_version`). Bump when the rule set changes.

## 4. Meta file shape

```json
{
  "fixture_version":       1,
  "sanitization_version":  1,
  "recorded_at":           "<UTC ISO at capture time>",
  "sport":                 "mlb|nba|nfl",
  "sgo_endpoint":          "/v2/events?league=MLB&…",  // key stripped
  "event_id":              "evt_…",
  "commence_time":         "<UTC ISO from SGO>",
  "books_seen":            ["draftkings","fanduel",…],
  "markets_seen":          ["team_total_runs",…],
  "outcomes_count":        <int>,
  "recorded_by":           "<operator id from CLI --recorded-by flag>",
  "git_sha":               "<short sha of HEAD when recorded>",
  "checksum_sha256":       "<sha256 of the sibling .json>"
}
```

## 5. Recording flow (Phase 1.A.3.3 — NOT YET WIRED)

```
operator $ export SGO_API_KEY=<real key>      # one-shot, in-shell
operator $ export TEAM_INGEST_ENABLED=1
operator $ python -m scripts.team_odds_fixture_record \
              --sport mlb --event-id evt_abc \
              --recorded-by ops-alice \
              --output backend/tests/fixtures/team_odds
```

Steps the CLI MUST perform (in order):

1. Verify both env vars set; abort with clear message if not.
2. Print a confirmation prompt with the FULL request URL (key
   already stripped from the printed line).
3. Wait for `y\n` on stdin.
4. Issue exactly ONE GET to SGO (no retries, no fan-out).
5. Pass response through `sanitize_response_bytes()`.
6. Run `assert_sanitized()` — fail loudly if any rule violated.
7. Compute the sibling meta file.
8. Write both files atomically (rename pattern).
9. Append a row to the auto-generated README.
10. Print absolute paths of the two new files.

## 6. Replay flow (Phase 1.A.3.2 — IMPLEMENTED IN `fixtures.py`)

```python
from services.team_master_hub.fixtures import load_fixture
payload, meta = load_fixture("backend/tests/fixtures/team_odds/mlb/2026-06-02_evt_001.json")
result = await worker.run_pass(db, payload, snapshot_iso=meta["recorded_at"], mode="dry_run")
```

- `load_fixture` re-runs `assert_sanitized()` on every read. If a
  fixture is later edited and a rule is violated, the LOADER aborts
  the test, NOT the worker.
- `load_fixture` verifies the `checksum_sha256` from the meta file
  matches the byte content of the JSON file.

## 7. Refresh policy

Refresh a fixture when ANY of:

- SGO market keys change (caught at Tier 3 by the market-explosion
  kill switch — operator records a fresh fixture to update the
  baseline).
- SGO outcome shape changes (`point` / `price` / `name` field rename).
- A new sport is added.

Stale fixtures are NOT deleted — they live as regression checkpoints.

## 8. Safety checklist before committing fixtures

- [ ] `assert_sanitized()` passed (CLI ran it)
- [ ] `git diff --stat` shows only `backend/tests/fixtures/team_odds/`
- [ ] No literal API key string in the working tree:
      `git grep -i sportsgameodds_apikey HEAD`
- [ ] Recorded URL in meta has no `api_key=…` param
- [ ] Operator name + git sha set in meta
- [ ] One full `pytest tests/test_team_odds_fixtures.py` run green

## 9. What is OUT OF SCOPE for Phase 1.A.3.2

- Mongo writes
- Worker code changes (the worker already reads any dict; the
